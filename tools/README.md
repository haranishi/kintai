# 点検の道具

点検の道具は Rust です（`crates/xtask`）。`cargo` だけで動きます。別実装（Python）と、その差分試験だけが Python で、標準ライブラリだけで動きます。PRの前は `cargo xtask check-all` を流してください。確かめたのはmacOSとLinuxです。Windowsでは試していません。`sh` と `git` を呼ぶ所があるためです。

| コマンド | 何をするか |
|---|---|
| `cargo xtask check-all` | 書式、clippy、全試験、文書、依存、仕様の対応、少数の差分試験、ライセンス表示を、まとめて流す（`--quick` で重い所を省く） |
| `cargo xtask check-links` | 文書の相対リンク切れ、公開されないファイルへのリンク、1ファイル100行の上限、ファイル名の禁止文字（`#` `\|` `[` `]` `^`）を検査する |
| `cargo xtask check-spec-trace` | 受け入れ条件（`AC-nn.n`）ごとに、試験からの参照があるかを一覧する（`--strict` で参照のない条件があれば失敗） |
| `cargo xtask mutate tools/mutations/<名前>.json` | ソースにわざと誤りを入れて、試験が赤くなるか（誤りを見つけるか）を確かめる（`--only 文字列` で絞る、`--keep` で作業場所を残す） |
| `cargo xtask bench` | 速さの測定の例（`crates/*/examples/bench_*.rs`）をまとめて流す（回数を引数で変えられる） |

## Python の部分

| 場所 | 何をするか | 使い方 |
|---|---|---|
| `oracle/` | 別実装。Rustの本実装を見ず、仕様だけから、1分ずつ数えて書いた | `python3 tools/oracle/selftest.py`（公的な数値例を再現するか） |
| `difftest.py` | 無作為のケースを、別実装と本実装の両方に通して、終了コードと出力を比べる | `python3 tools/difftest.py --cases 2000 --seed 1 --bin target/release/kintai` |
| `mutations/` | 変異の定義（JSON）。壊れると結果が狂う境界の誤りを、部品ごとに並べた | 新しい守りを足したら、外す誤りも足す |

別実装を本体と別の言語（Python）で書いたのは、本体と同じ読み違いや、同じ部品の癖を共有しないためです。Rustに移すなら、本体のコードや部品を共有せず、仕様だけから書く形が保てるかを、先にIssueで相談してください。

## 別実装を直すときの決まり

別実装は、本体と独立に書かれていることに価値があります。直すときは、`docs/spec/` の仕様だけを見て直し、Rustのコードを見ながら直さないでください。食い違いが出たら、どちらが正しいかを仕様で決め、仕様が決めていなければ、先に仕様を直します（[開発の手引き](../docs/development.md)）。

## 差分試験の見方

`--stats` を付けると、生成したケースの分布と、境界を踏んだ件数が出ます。不一致があると、ケースを `tools/difftest-out/` に残し、先頭の数件を詳しく表示して、終了コード1で終わります。比べるのは、終了コード、終了コードが0か4のときの出力のJSON、2か3のときの `error.code` です（`message` は比べません）。本実装が見つからないときは失敗にします（別実装だけを動かすなら `--oracle-only`）。
