# 速さの測定

[非機能の仕様](spec/nfr.md)の速さの目標を、測った結果です。測定の例は `crates/*/examples/bench_*.rs` にあり、`cargo xtask bench` でまとめて流せます。データはすべて合成で、乱数を使わない決まった式から作るので、何度流しても同じ入力です。

## 結果

| 項目 | 目標 | 最良 | 中央値 | 条件 |
|---|---:|---:|---:|---|
| 区分の計算 | 100ミリ秒 | 6.9ミリ秒 | 6.9〜7.4ミリ秒 | 1,000人×31日、勤務27,457件。勤務の検査（`ShiftSet::new`）から区分（`classify`）まで |
| 36協定の年間判定 | 50ミリ秒 | 0.93ミリ秒 | 0.94〜0.98ミリ秒 | 1,000人×12か月と履歴5か月。協定の検査（`Agreement::validate`）から判定（`judge`）まで |
| 打刻CSVの取込 | 3,000ミリ秒 | 114ミリ秒 | 117〜122ミリ秒 | 100万行（約33MB、UTF-8、LF）。入力の上限の検査（`read_limited`）から読み取り（`read_punches`）まで |
| 起動 | 50ミリ秒 | 1.3ミリ秒 | 1.6〜1.9ミリ秒 | `kintai --version` を200回動かした1回あたり |

4項目とも、目標の1割に届きませんでした。判定は中央値で行っています。表の幅は、`cargo xtask bench` を3回流したときの範囲です（各項目は慣らし1回のあと7回）。

## 条件

- 機械: Apple M4 Pro（14コア、48GiB）。OS: macOS（Darwin 27.0.0）。Rust: rustc 1.99.0。
- プロファイル: `--release`（ワークスペースに `[profile.release]` がないので、Cargoの既定。opt-level=3、lto=false、codegen-units=16）。
- 測定中も、ほかの作業が動いていました（負荷の平均は約5）。静かな機械で測れば、もっと速くなる可能性があります。

## メモリ（参考）

独立した査読の測定では、入力の上限いっぱいの打刻CSV（256MiB、約880万行、2,000人）の `report` で、最大メモリは約2GB（入力の約7倍）、時間は約3.7秒でした。メモリの少ない機械で上限近くを読むときは、従業員ごとにCSVを分けてください。仕様に、メモリの上限は書いていません。

## 何を測っていないか

- **ディスクの読み込み。** 取込の測定は、メモリ上のバイト列から読む時間です。実際のファイルでは、保存先の速さが加わります。
- **36協定の判定に、区分の計算は含みません。** 区分の結果から月ごとのOとHを取り出す部分と、判定の部分を別に測っています。
- **コマンドの出力の整形。** JSONやCSV、人が読む表を作る時間は含みません。
- **ほかの機械、ほかのOS。** Linux、Windows、古い機械では測っていません。

## 再現するには

```sh
cargo xtask bench        # 各項目を慣らし1回のあと7回。目標を超えた項目があれば終了コード1
cargo xtask bench 11     # 回数を変える（3以上）
```

読み取り専用で、実データには触れません。
