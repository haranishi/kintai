# 打刻は2タップ、月を閉じる前は「閉じられない理由」を先に見せる（UXの5階層）

Phase 1 の画面を作る前に、戦略から表層までを一度通した記録です。設計は9か所変わりました（末尾）。物語は[ユーザーストーリー](stories.md)にあります。利用者調査は、まだありません。数字と判断の多くは、作者の仮説で、実際の事業者に試してもらう前の見立てにすぎません。

## 戦略: 従業員1〜30人の事業者が、自社で動かせる勤怠

使い手は3人です。打刻する従業員、承認する店長、月を閉じる事業主です。事業主は、勤怠の記録を外のサービスに預けず、賃金台帳に写す時間数を、条文の根拠つきで出したいと仮定しています。

成功の基準は3つで、どれも目標です。従業員が出勤を記録するまで、ホームから2回のタップ以内。架空の10人×1か月の打刻から、月を閉じて書き出すまで、管理者が15分以内。開発者が起動して最初の打刻をするまで、15分以内。

## 要件: 11の物語

柱は4つです。打刻して、今日と今月を見る（US-21・22）。修正と休暇を申請し、承認する（US-23〜25）。方針を決めて、月を閉じ、書き出す（US-26〜28）。記録が壊れていないことを確かめ、理由を読む（US-29・30）。作らないものは、位置情報や顔認証による打刻、36協定届の作成、給与の金額の計算（Phase 2）です。

## 構造: 役割ごとに入口が違い、記録は追記だけ

```
従業員: 打刻 / 今日と今月 / 申請（修正・休暇） / 履歴 / 理由（explain）
承認者: 承認待ち / 今日のチーム            管理者: 月の進行 / 従業員 / 方針 / 月を閉じる / 書き出し / 整合性とバックアップ
```

誰の画面でも、記録を書き換える操作は無く、足す操作だけです。取り消しも修正も、理由つきの新しい記録になります。この違いが、画面と保存の構造を決めます。

## 骨格: ホームは1つの大きなボタン

従業員のホームは、今の状態に合わせて変わる1つの大きなボタンと、今日の記録の一覧だけです。出勤前は「出勤」、勤務中は「退勤」と「休憩開始」の2つ、休憩中は「休憩終了」になります。押すと、サーバーの時刻と新しい状態をすぐ示し、60秒以内なら「取り消し」が押せます。

承認の画面は、1件ずつ縦に並べます。修正の承認では、承認した場合の本人の月の時間外と、36協定の上限までの残りを、承認ボタンの上に示します。

月を閉じる画面は、ボタンでなく確認の一覧です。閉じられない理由（打刻の異常、休憩の不足、曖昧さによる拒否、36協定の違反と判定不能、承認待ち）を先に示し、全部に目を通したことを示してから、閉じる操作を押せます。

## 表層: 落ち着いた色と、押し間違えない大きさ

タップできる大きさは44px以上。数字は等幅で右に寄せます。色は藍を主にし、赤は違反と取り消しにだけ使います。注意は橙で、必ず文字でも示します。明暗はOSに従い、フォントは端末標準の日本語書体です。外部の読み込みは無く、画面の文字は `textContent` で作ります。文字と背景は4.5:1以上を、色の定義から計算して確かめます。

## 通したことで変わった9つの決定

1. [戦略] 打刻の時刻はサーバーの時計で決め、端末の時計は使わない。端末の時計は直せるため。
2. [要件] 「取り消し」は削除でなく、60秒以内の新しい記録にする。追記だけの原則を保つため。
3. [要件] 管理者も打刻を直接は書き換えない。管理者の修正も理由つきの記録にする。
4. [構造] 承認の画面に、承認した場合の影響（時間外と上限までの残り）を先に示す。
5. [構造] 月を閉じるのは、ボタンでなく確認の一覧にする。閉じた後の再計算は、別の版として足す。
6. [構造] 対応外の働き方は、従業員を登録した時点で断る。月末に分かるのでは遅いため。
7. [骨格] 従業員は自分の記録と36協定の残りだけ見える。他人のは見えない。
8. [骨格] 修正の履歴は、元の値と直した値を並べて見せる。透明にするため。
9. [表層] 色だけに頼らない。80%を超えたら橙と文字、違反は赤と文字。
