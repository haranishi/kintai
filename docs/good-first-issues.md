# 最初の貢献の候補

初めての人向けに、小さく始められる作業を並べました。どれも、期待する結果と、対象のファイル、完了の確かめ方が決まっています。やりたいものがあれば、先にIssueで「これをやります」と書いてください（重複を避けるためです）。進め方は[参加の手引き](../CONTRIBUTING.md)、手元での動かし方は[開発の手引き](development.md)にあります。

返信の目安は1週間です。この一覧の作業は、受け入れる前提で用意しています。マージの可否は、保守者のレビューで決まります。

## コードを書かない作業

### 1. 労務の専門家として、確認シートの1行に答える（難しさ: 専門知識）

[確認シート](legal/professional-review.md)の行は、公的な資料だけでは読みが決まらなかった点です。社会保険労務士や人事労務の実務に詳しい方は、1行だけでも構いません。
- 完了: 行のID（`P-01` など）を指して、「問題なし」「直す（こう直す）」「判断できない」のどれかと理由、資格か経験の範囲をIssueに書く。

### 2. 初めて使う人として、はじめかたを試す（易）

[はじめかた](getting-started.md)の手順だけで、15分以内にデモの出力を読めるかを試してください。
- 完了: つまずいた所（環境、コマンド、言葉）をIssueに書く。OSとRustの版を添える。WindowsとLinuxの結果は特に助かります。

### 3. 試験データの出典を点検する（易）

`docs/spec/vectors/` の各例には、出典のURLと引用が付いています。リンクが生きているか、引用が出典と一致しているかを見てください。
- 完了: 切れたリンクや、一致しない引用を、確認した日つきでIssueに書く。直す場合は、数値が変わらないことを `cargo test -p kintai-jp-labor` で確かめる。

### 4. READMEの英訳（易）

README.en.md が無いので、英語の読者が概要をつかめません。
- 完了: READMEの意味を変えずに訳す。法令用語は、日本語を括弧で添える。免責の段落は、弱めずに訳す。

## 小さなコードの作業

### 5. 2051〜2099年の春分・秋分を、独立した計算で照合する（中）

2050年までは国立天文台の予想表と近似式が一致しています。2051年以降は公的な表が無く、未検証です。
- 対象: `crates/kintai-jp-labor/src/holidays.rs`、[祝日の仕様](spec/holidays.md)。
- 完了: 近似式とは別の方法（天文計算）で2051〜2099年の日付を出し、食い違う年を一覧にしたレポートをIssueに書く。食い違いが無ければ、その確認を試験として足す。

### 6. まだ試験の無い受け入れ条件に、試験を足す（中）

```
python3 tools/check-spec-trace.py
```

を流すと、試験からの参照が無い条件が並びます。1つ選んで、試験を足してください。試験の名前かコメントに、条件の番号（`AC-06.1` など）を書きます。
- 完了: 足した試験が通る。わざと実装を壊して、試験が赤くなることも確かめる（`tools/mutate.py` が使えます）。

### 7. 合成の打刻データを足す（易）

夜勤で日をまたぐ、月の変わり目をまたぐ、休憩を取らない、といった場面の合成CSVを足します。
- 対象: `tests/fixtures/synthetic/`。
- 完了: 実在の氏名・会社・店を使わない。`kintai report` の出力を期待値として、`crates/kintai-cli/tests/` に試験を足す。

### 8. 変異試験の穴を探す（中）

`tools/mutations/*.json` は、壊れると結果が狂う所に、わざと誤りを入れて試験が赤くなるかを見る定義です。
- 完了: 新しい変異を1〜3件足し、赤くなることを `python3 tools/mutate.py tools/mutations/<名前>.json` で確かめる。生き残る（赤くならない）変異を見つけたら、それが成果です。試験を足して赤くなるようにする。

## 相談してから始める作業

次は、先にIssueで設計を相談してください。仕様の変更と、対応外の働き方を計算できるようにする作業が含まれます。

- 対応外の働き方（1か月単位の変形労働時間制など）を計算できるようにする。法令の根拠と、公的な数値例を添えること。
- 管理簿やレポートの様式の追加。
- 公開するAPIの変更、依存の追加。
