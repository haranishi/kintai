# 仕様: 36協定の上限の判定

月ごとの時間外・休日労働から、労基法36条4項・5項の月と年の時間と、6項2号・3号の上限を満たしているかを判定します。根拠は `.agent-harness/runs/2026-10-15-phase0/research/track-B.md` のQ1・Q2・Q3と、査読 `review-l1.md` です。**判定しないもの**は、6項1号（坑内労働などの1日2時間）、協定の1日の延長時間と休日労働の日数、協定の有効性、届出、健康確保措置です。

## 用語

- **協定月**: 協定の対象期間の初日（協定年の起算月、日は方針の `month_start_day`）から1か月ごとに区切った期間。60時間超の「月の期間」と同じ起算日を共有する（違う方針は対応外）。協定月の初日は1〜28日で、29〜31日は不正な入力。
- **協定年**: 協定月12個。起算月は `agreement36.year_start_month`（必須）。
- 協定月 m の **O**: 法定時間外の分（法定休日労働を含まない）。**H**: 法定休日労働の分。**T = O + H**。OとHは同じ分を二重に数えない。法定外休日の労働は、日・週の法定時間を超える分だけがOになる。
- **副業・兼業先と転職前の時間**: 月100時間未満と2〜6か月平均80時間の上限は、自社以外の時間も通算して適用される（厚生労働省『改正労働基準法に関するQ&A』2-32）。この版は、入力されたT（`history` を含む）だけを判定する。通算した値を渡すのは呼び出し側で、出力の `notices` に `OwnEmployerOnly` を必ず付ける。

## 判定

協定の種類は `none`（協定なし）、`general`（一般条項）、`special`（特別条項つき）。**発動月**は、O > 2700分（法定の月45時間）の月。

1. `none`: O > 0 または H > 0 の月は違反（`NoAgreement`）。
2. 常に（協定の種類によらず）: 各月の **T < 6000分**（100時間ちょうどは違反）。各月と n = 2〜6 について、その月までの直近 n か月の **T の合計 ≤ 4800 × n 分**（平均80時間ちょうどは適合）。平均は割らず、合計で比べる。直近 n か月は協定年をまたぐ。
3. 一般条項（`general` と `special` の両方）: O が2700分以下で、協定の月限度（`monthly_limit_minutes`。必須で、2700分以下）を超える月は `GeneralMonthlyLimitExceeded`。
4. `general`: O > 2700分の月は `MonthlyOvertimeExceeded`。協定年の始めからの ΣO が21600分を超えた月は `AnnualOvertimeExceeded`。21600分以下で協定の年限度（`annual_limit_minutes`。必須で、21600分以下）を超えた月は `GeneralAnnualLimitExceeded`。
5. `special`: 発動月の数（協定年の始めから）が協定の回数（≤ 6）を超えた発動月は `SpecialCountExceeded`。発動月の T が協定の月の上限（≤ 5999分）を超えれば `SpecialMonthlyTotalExceeded`。年の始めからの ΣO が協定の年限度（≤ 43200分）を超えた月は `SpecialAnnualExceeded`。720時間は通常分を含む総量で、360時間に足す枠ではない。
6. 履歴が足りないとき（直近 n か月のうち、データも履歴も無い月がある）は、その n の合計を `null`、判定を `UnknownHistory`（n つき）とする。無い月を0分とみなして適合にしない。
7. 協定年が替わると、ΣO と発動月の数は0に戻る。直近 n か月の合計に使う履歴は戻らない。
8. 累計で決まる違反（`AnnualOvertimeExceeded` `GeneralAnnualLimitExceeded` `SpecialAnnualExceeded`）は、累計が超えた月から協定年の終わりまで、毎月付く（その月の O が0でも）。`SpecialCountExceeded` は、回数が超えた**発動月**だけに付き、発動月でない月には付かない。
9. `months` の最初の月が協定年の途中のとき、その年の ΣO と発動月の数は、`months` にある月だけの下限値になる（前の月の O は `history` に無い）。その年の月は `year_overtime_known` が偽になる。偽のときは、下限値に同じ規則を当てて、確実に超えている違反だけを出し（年限度を超え21600分以下なら `GeneralAnnualLimitExceeded`、21600分を超えれば `AnnualOvertimeExceeded`）、出ないことは適合を意味しない。協定年の初月から `months` に入れれば真になる。

対象外の業務と労働者は[対応外の仕様](unsupported.md)で拒否する。協定上の限度が法定の最大値を超える設定は、不正な入力にする。

## 公的な数値例（`vectors/limits36-official.json`）

厚生労働省『時間外労働の上限規制 わかりやすい解説』p.16〜17、p.21、p.4の例。時間は分に換算する。p.21の例は合計だけを示すので、Oと日の分け方は試験の仮定。

- 2021/4〜9: O＝80,60,45,35,35,80時間、H＝0,20,15,10,0,0時間。T＝80,80,60,45,35,80時間。2021/9の直近2〜6か月の合計は115,160,220,300,380時間（平均57.5,53.3,55.0,60.0,63.3）。発動月の累計は1,2,2,2,2,3。協定は年680時間、月85時間、6回。
- 2020/11〜2021/4: O＝45,45,30,20,45,80、H＝0,10,0,0,0,0。2021/4の直近2〜6か月の合計は125,145,175,230,275時間。
- 違反: 4月〜翌3月のOが46,10を交互に繰り返し最後が46,46（45時間超が7回）。T＝10,10,100,…（6月が100時間）。T＝…,85,70,90,10（12〜2月の3か月合計245時間＞240）。O＝44、H＝56（T＝100）。

## 受け入れ条件

- AC-05.1 [rust] OとHを、分類の結果から取り出し、T＝O＋Hとする。二重に数えない。
- AC-05.2 [rust] 協定なしでは、O または H があると違反にする。
- AC-05.3 [rust] 一般条項の月と年の限度（法定の最大より小さくてもよい）で検査し、法定の45時間・360時間を超えた場合と、協定の限度だけを超えた場合を、別のコードにする。
- AC-05.4 [rust] 特別条項では、発動月の数、年のΣO、発動月のTの上限を検査する。
- AC-05.5 [rust] Tが6000分ちょうどは違反、5999分は適合にする。
- AC-05.6 [rust] 直近2〜6か月のTの合計が 4800×n ちょうどは適合、1分超は違反にする。丸めた平均を使わない。
- AC-05.7 [rust] 履歴が足りない判定は `UnknownHistory` にし、0分として扱わない。
- AC-05.8 [rust] 協定年の替わりで ΣO と発動月数は戻り、直近 n か月の合計は戻らない。
- AC-05.9 [rust] 公的な数値例の合計と、違反の判定がすべて一致する。
- AC-05.10 [rust] 協定の限度が法定の最大を超える設定は、不正な入力にする。
- AC-05.11 [python] 無作為の月別の時間で、別実装と判定が全件一致する。
- AC-05.12 [rust] 発動月はOが2700分を超える月で数える。協定の月限度が2700分より小さい協定で、その限度を超え2700分以下の月は、発動月に数えず `GeneralMonthlyLimitExceeded` にする。
- AC-05.13 [rust] 出力の `notices` に `OwnEmployerOnly` が必ず付く。
- AC-05.14 [rust] 年の累計の違反は超えた月以降の毎月に付き、`SpecialCountExceeded` は発動月だけに付く。
- AC-05.15 [rust] 協定年の途中から始まる入力で `year_overtime_known` が偽になり、下限値で確実な違反だけを出す。
