# 仕様: 年次有給休暇の付与・残数・5日取得義務・管理簿

労基法39条と労基則24条の3〜24条の7に沿って、付与日数、2年の時効、残数、年5日の取得義務、管理簿を計算します。根拠は `.agent-harness/runs/2026-10-15-phase0/research/track-C.md` のQ1〜Q6と、査読 `review-l1.md` です。数値例の出典は付与表（条文）と、厚生労働省『年5日の年次有給休暇の確実な取得 わかりやすい解説』です。

## 範囲

対応するのは、雇入れ日から6か月で最初の付与があり、以後1年ごとに付与する通常の運用です。付与日を前倒しする設定（入社日に10日付与など）は、従業員の項目 `grants` に付与日と日数を明示して使う。対応外（拒否する）は、次の順に見る。時間単位の年休（`LeaveHourly`）。分割付与（`LeaveSplitGrant`: `grants` を付与日の昇順に並べ（同じ日は入力の順）、10日（20半日）未満の付与の次の付与が、`次の初日(その付与日, 12)` より前にある）。付与日数の表に当たらない場合（`LeaveOutOfTable`: 下の2の①に当たらず、②で年間所定労働日数が48日未満、または③で週の所定労働日数が0日）。対応外の判定では、`as_of` と日付が正しい書式（範囲の外でもよい）で、`as_of` より後の取得と付与は入れない（予定の記録で、いま計算する範囲ではないため）。書式の誤りは入れたまま判定し、日付の検査（手順4）で不正な入力になる。ただし `grants` に書式の誤りのある付与日があるときは、並べられないので、分割付与の判定をしない（手順4で不正な入力になる）。第二基準日の期間を結合する按分の特例は扱わない。重なる5日の期間は、両方に数える（下の6）。検査の順序は[検査の順序](validation.md)と同じ流儀で、日付の書式と整合の検査は対応外の後。

## 日付の規則（民法143条2項）

月・年で数える期間は、暦に従う。起算日の応当日の前日に満了し、最後の月に応当日がなければ、その月の末日に満了する。期間の次の日が、次の期間の初日。

- `期間の終わり(S, n)`: 日付 S から n か月の期間の最後の日。S の n か月後に同じ日付があれば、その前日。なければ、その月の末日。
- `次の初日(S, n)`: `期間の終わり(S, n)` の翌日。
- **最初の付与日（六箇月経過日）** g0 = `次の初日(雇入れ日, 6)`。k 回目の付与日 g_k = `次の初日(g0, 12k)`。**g0 から数える**（前回の付与日から1年ずつ足すと、2月29日が一度ずれると戻らない）。
- **失効日** = `次の初日(付与日, 24)`。この日の当日は使えない（前日まで使える）。
- **5日の期間** = 付与日から `期間の終わり(付与日, 12)` まで。

例: 雇入れ2023-08-29 → g0＝2024-02-29、g1＝2025-03-01、g2＝2026-03-01、g3＝2027-03-01、g4＝2028-02-29。g0 の失効日は2026-03-01（2026-02-28まで使える）、5日の期間は2024-02-29〜2025-02-28。

## 規則

1. **付与日**: 上の g_k。`as_of` より後の付与日のロットは出さない（`grants` の明示も同じ）。
2. **付与日数**: ①週の所定労働日数が5日以上、または週の所定労働時間が1800分以上なら通常付与（6か月、1年6か月…で10,11,12,14,16,18,20日。6年6か月以後は20日）。②そうでなく年間所定労働日数があれば、週の日数より優先してその区分を使う（217日以上は通常付与、169〜216日は週4日、121〜168日は週3日、73〜120日は週2日、48〜72日は週1日の行、48日未満は `LeaveOutOfTable`）。③それ以外は、労基則24条の3の表の週の日数の行（週4日: 7,8,9,10,12,13,15／3日: 5,6,6,8,9,10,11／2日: 3,4,4,5,6,6,7／1日: 1,2,2,2,3,3,3）。週0日は `LeaveOutOfTable`。
3. **出勤率**: 従業員の項目で、付与ごとに `meets`（8割以上）、`below`、`unknown` を与える。`below` の年は付与しない（勤続年数は戻さない）。`unknown` は付与し、`AttendanceUnconfirmed` の注意を付ける。出勤率そのものはこの版では計算しない。`grants` を明示したときは使わず、注意も付けない。
4. **ロット**: 付与ごとに、付与日、日数、失効日を持つ。
5. **取得**: 取得の記録は日付と単位（`full`＝1日、`half`＝0.5日）。日付順に、その日に使えるロット（付与日 ≤ 日付 < 失効日）の古いものから消化する。残数が足りない記録は不正な入力。`as_of` より後の記録は数えず、残数の検査もしない。1日（`full`）の取得は2半日で、残り半日のロットと次のロットにまたがってよい。同じ日の複数の記録は、そのまま数える。
6. **5日取得義務**: 付与日数が10日以上の付与ごとに、5日の期間の取得（全日と半日、請求・計画付与・時季指定のどれも、繰越分の取得も）の合計が5日以上なら `Met`。期間は重なってよく、重なる日は両方の期間に数える（条文の読みで、公的な明示はない）。`as_of` が期間の終わりを過ぎて5日に満たなければ `NotMet`、期間内なら `InProgress`（あと何日）。10日未満の付与は `NotApplicable`。比例付与でも、10日以上になる付与は対象（週4日は3年6か月以後、週3日は5年6か月以後）。`NotMet` は、休業などで取得が不可能だった場合は違反でない（通達 答6）ので、違反と断定しない。
7. **管理簿**: 付与ごとに、基準日（付与日）、付与日数、5日の期間に入る取得の日付と単位、取得日数の計。

## 保存の目安

管理簿は、付与の期間中と満了後5年が本則で、労基則の附則71条により当分の間3年に読み替える。人が読む出力（`kintai leave`）と `kintai retention` に両方を示し、製品の既定は5年にする。ケースのJSONには欄を作らない。自動で削除しない。

## 受け入れ条件

- AC-06.1 [rust] 付与表（通常7行、比例28セル）が条文と全セル一致する。
- AC-06.2 [rust] 付与日・失効日・5日の期間が、日付の規則で決まる。2023-08-29入社の例（g0〜g4、失効、期間）が一致する。
- AC-06.3 [rust] 出勤率 `below` の年は付与せず、勤続年数は進む。`unknown` は付与して注意を付ける。
- AC-06.4 [rust] ロットが失効日の当日に失効し、古いロットから消化される。
- AC-06.5 [rust] 半日が0.5日として、残数と5日の取得に数えられる。
- AC-06.6 [rust] 5日取得義務が、10日以上の付与だけに、5日の期間で判定され、`NotMet` の状態名になる。
- AC-06.7 [rust] 繰越分の取得と、重なる期間の取得（導出）が、読みどおりに数えられる。
- AC-06.8 [rust] 公的な数値例（期間の日付）が一致する。
- AC-06.9 [rust] 対応外（時間単位、分割付与、48日未満、週0日）が、定めた順に拒否される。
- AC-06.12 [rust] 付与日数の優先順位（週5日以上か週1800分以上 → 年間の日数 → 週の日数）が、定めた順になる。
- AC-06.10 [rust] 管理簿の行が出る。残数が足りない記録は不正な入力になる。`as_of` より後の付与と取得は出ない。
- AC-06.11 [python] 無作為の入力で、別実装と全件一致する。
