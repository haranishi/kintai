# 仕様: 非機能の要件（速さ、決定性、安全、個人情報）

数字は**目標**です。測って、確かめて公開するまでは、READMEで「達成した」と書きません。測定の結果と方法は `docs/benchmarks.md` に書きます。

## 速さ

| 項目 | 目標 | 条件 |
|---|---|---|
| 区分の計算 | 100ミリ秒以内 | 1,000人×1か月（約3万日）、合成データ。入出力を除く計算だけ |
| 36協定の年間判定 | 50ミリ秒以内 | 1,000人×12か月 |
| 打刻CSVの取込 | 3秒以内 | 100万行の合成データ（UTF-8） |
| 起動 | 50ミリ秒以内 | `kintai --version` |

測るのは `--release` のビルドで、測定用の例（`crates/*/examples/bench_*.rs`）を `cargo xtask bench` でまとめて流す。

## 決定性

- 同じ入力は、いつ、どの環境で動かしても、まったく同じ出力のバイト列になる。
- 出力の順序は、日付順、従業員ID順など、仕様で決める。ハッシュの走査順に依存しない。
- 現在の時刻、乱数、環境変数、ロケールを、計算に使わない。基準の日付は引数で受ける。
- 浮動小数点を使わない。金額に当たる値も、時間も、整数。

## 安全

- `unsafe` を使わない（`unsafe_code = "forbid"`）。
- どんな入力（壊れたCSV、JSON、TOML、任意のバイト列）でも、パニックせず、不正な入力のエラーで終わる。
- 入力の上限：ファイル256MiB、1行4KiB（改行を除く4096バイト）、従業員10万人、1人あたり1か月の勤務1,000件、日付は2000-01-01〜2099-12-31。超えたら不正な入力。
- 整数の桁あふれを起こさない（`i64` の範囲と上限の検査）。
- 外へ通信しない。HTTPやソケットを扱う依存を持たない（`deny.toml` で禁止し、依存の一覧を `cargo tree` で確かめる）。
- 依存は許可リスト（`csv` `encoding_rs` `serde` `serde_json` `toml` `pico-args`。試験のみ `proptest` `chrono`）に限る。追加は先に相談する。

## 個人情報

- 従業員の氏名は、この版では扱わない。識別は従業員ID（`[A-Za-z0-9][A-Za-z0-9._-]{0,63}`）だけ。
- エラーの文には、入力の行の中身を含めない。行番号と列名だけを示す。
- 標準出力以外に書くとき（`demo --out`、`--out`）は、フォルダを0700、ファイルを0600で作る（Unix系）。
- 計測・送信・ログの記録をしない。

## 受け入れ条件

- AC-10.1 [rust] 区分の計算が、1,000人×1か月で100ミリ秒以内（測定用の例で測る）。
- AC-10.2 [rust] 36協定の年間判定が、1,000人で50ミリ秒以内（同上）。
- AC-10.3 [rust] 100万行の打刻CSVの取込が3秒以内（同上）。
- AC-10.4 [rust] 同じ入力で、出力のバイト列が毎回一致する。
- AC-10.5 [rust] 任意のバイト列・壊れたJSON/TOML/CSVで、パニックしない（性質の試験）。
- AC-10.6 [rust] 入力の上限を超えると、不正な入力になる。
- AC-10.7 [rust] エラーの文に、入力の行の中身が含まれない。
- AC-10.8 [rust] `demo --out` が0700/0600で作る（Unix系）。
- AC-10.9 [manual] 依存に、通信を扱う部品がない（`cargo tree` と `deny.toml` の禁止リスト）。
